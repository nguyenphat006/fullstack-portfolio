Admin Template — Full-stack Admin Template

Những gì cần biết để dùng template: có sẵn gì, cấu trúc ra sao, viết tính năng mới thế nào và đưa lên production.

Django 5.2 LTSDRF 3.17PostgreSQL 16Redis · Celery Next.js 16React 19Ant Design 6TanStack Query 5TypeScript

Tổng quan

Clone về, đổi thương hiệu, chạy bootstrap là có hệ thống quản trị hoàn chỉnh. Phần việc còn lại chỉ là tính năng riêng của đề tài.

Tài khoản

Đăng nhập JWT

Access + refresh tự làm mới, hồ sơ cá nhân, đổi mật khẩu, đăng xuất (blacklist token).

Phân quyền

RBAC động

Phân hệ → quyền → vai trò; ma trận phân quyền trên giao diện; menu và nút tự ẩn theo quyền.

Người dùng

Quản lý tài khoản

CRUD, khóa/mở hàng loạt, nhập/xuất Excel, trang hồ sơ chi tiết.

Hệ thống

Nhật ký & đính kèm

Nhật ký thao tác tự động bằng trigger PostgreSQL; tệp đính kèm cho mọi thực thể, xem trước PDF/Word/Excel/ảnh.

Giao diện

Sáng / tối / mobile

Theme theo hệ thống, sidebar ngăn kéo trên điện thoại, trang 404 / lỗi / loading, trạng thái hệ thống thật.

Công cụ

Sinh module & vận hành

startmodule + gen:module, Docker production, CI, Dependabot, smoke test Playwright.

Kiến trúc

Trình duyệt→nginx→Next.js (client/)+Django REST (server/)→PostgreSQL·Redis·Celery
Hợp đồng API: mọi response JSON có dạng {success, message, data, errors, code}. Backend sinh server/schema.yml (OpenAPI), frontend sinh kiểu TypeScript từ file đó, nên hai phía luôn khớp nhau.

Backend — Django REST

Mọi thực thể nghiệp vụ dựa trên 3 thứ: AuditModel, BaseERPViewSet và ModulePermissionChecker.

Nền tảng trong apps/core

Thành phầnViệc nó làm cho bạn
AuditModelThêm sẵn created_at/updated_at, created_by/updated_by, description, is_active, xóa mềm (deleted_at). objects ẩn bản ghi đã xóa, all_objects lấy tất cả.
BaseERPViewSetCRUD kèm thông điệp tiếng Việt, statistics, batch-delete, batch-status, xuất/nhập Excel (tự chạy nền khi dữ liệu lớn).
Renderer + exception handlerBọc mọi response thành envelope; chuẩn hóa lỗi thành errors: {field: [...]} kèm code ổn định.
ModulePermissionCheckerSuy ra quyền từ action (list → X_READ, export_excel → X_EXPORT…); chặn mặc định khi thiếu cấu hình.
/api/v1/health/Kiểm tra CSDL + cache; dùng cho Docker healthcheck và Dashboard.

Viết một ViewSet

class SupplierViewSet(BaseERPViewSet):
    queryset = Supplier.objects.select_related('created_by', 'updated_by').order_by('-updated_at', 'id')
    serializer_class = SupplierSerializer                   # đọc: dùng cho MỌI response
    write_serializer_class = SupplierCreateUpdateSerializer  # ghi: create / update
    permission_classes = [IsAuthenticated, ModulePermissionChecker]
    permission_module = 'SUPPLIER'
    filterset_fields = ['is_active']
    search_fields = ['code', 'name']

    def check_can_destroy(self, instance):            # áp dụng cả xóa đơn lẫn hàng loạt
        if instance.purchase_orders.exists():
            raise BusinessError("Nhà cung cấp đang có đơn mua hàng.")

Hợp đồng response

// Thành công (danh sách: data = {count, total_pages, current_page, page_size, next, previous, results})
{ "success": true,  "message": "Thêm mới nhà cung cấp thành công", "data": {...}, "errors": null, "code": null }
// Thất bại
{ "success": false, "message": "Mã đã tồn tại.", "data": null, "errors": { "code": ["Mã đã tồn tại."] }, "code": "validation_error" }
Lỗi luôn raise, không return: serializer.is_valid(raise_exception=True), raise BusinessError(...), raise NotFound(...). Không tự dựng Response(errors, 400).

Phân quyền RBAC

ModuleRegistry (phân hệ + menu)→Permission <CODE>_<ACTION>→Role→User

Khai báo trong seed_core.py: một phân hệ trong DEFAULT_MODULES + *crud_permissions('SUPPLIER', 'nhà cung cấp') (sinh 7 quyền VIEW/READ/CREATE/UPDATE/DELETE/EXPORT/IMPORT). Superuser và vai trò ADMIN có mọi quyền.

  • Chỉ Quản trị viên được gán vai trò ADMIN / sửa tài khoản Quản trị viên; không ai tự đổi vai trò của mình; không có mật khẩu mặc định.
  • Tệp đính kèm: quyền theo thực thể cha, tải qua link ký hết hạn 1 giờ.
  • Frontend: RouteGuard trả 403 cho URL ngoài menu; nút ghi chỉ hiện khi View truyền handler (đã kiểm tra can()).

Thêm tính năng mới

Với thực thể dạng danh mục (mã, tên, mô tả, trạng thái), hai lệnh sinh ra gần như toàn bộ code. Bạn chỉ bổ sung trường nghiệp vụ.

  1. Chốt thiết kế trong DBMLMọi bảng/cột mới có trong server/database.dbml trước khi code.
  2. Sinh backend
    cd server
python manage.py startmodule suppliers Supplier --label "nhà cung cấp" --route master-data/suppliers --parent MASTER_DATA
    Tạo apps/suppliers/ (model, serializer, ViewSet, urls, test), tự đăng ký settings/urls/quyền và in ra bảng DBML.
  3. Thêm trường nghiệp vụ & migrate
    python manage.py makemigrations suppliers && python manage.py migrate && python manage.py seed_core
python manage.py test apps.suppliers && python manage.py spectacular --file schema.yml
  4. Sinh frontend
    cd ../client
npm run gen:api
npm run gen:module -- --entity Supplier --label "nhà cung cấp" --route master-data/suppliers
    Tạo types, service, hook, bảng, bộ lọc, form, view, route và mã quyền.
  5. Kiểm tranpx tsc --noEmit → antd lint ./src → npm run build. Menu tự hiện theo quyền.
Windows / Git Bash: viết --route master-data/suppliers (không có "/" đầu), vì Git Bash tự đổi /abc thành đường dẫn ổ đĩa.
Thực thể phức tạp (cây phân cấp, chứng từ nhiều dòng, wizard): làm thủ công theo mẫu master_data/materials. Quy trình đầy đủ nằm trong skill .claude/skills/new-module/SKILL.md.

Vận hành

Production bằng Docker

cp .env.prod.example .env.prod      # SECRET_KEY, POSTGRES_PASSWORD, ADMIN_PASSWORD, ALLOWED_HOSTS…
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
nginx :80→/api /admin /static → api (gunicorn)·/media → volume·/ → web (Next standalone)

api

Khởi động bằng bootstrap (migrate + seed_core, không ghi đè dữ liệu) rồi gunicorn; healthcheck /api/v1/health/; chạy bằng user không phải root.

worker

Celery xử lý xuất/nhập Excel lớn; dùng chung volume media.

web

Next.js standalone, NEXT_PUBLIC_API_URL=/api/v1 được đóng vào bundle lúc build.

HTTPS: đặt sau proxy có TLS (Caddy, Cloudflare, Traefik…), rồi bật SECURE_SSL_REDIRECT=True và CSRF_TRUSTED_ORIGINS.
