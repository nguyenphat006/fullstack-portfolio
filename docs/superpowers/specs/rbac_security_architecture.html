1. 5 Nguyên Tắc Thiết Kế Cốt Lõi (Core Principles)

1. Type-Safe Permissions (Zero Magic Strings)

Toàn bộ mã quyền được kiểm soát qua Enum/Constants tập trung. Gõ sai chính tả lập tức bị trình biên dịch TypeScript và Python bắt lỗi.

2. Phân tách VIEW vs READ

VIEW kiểm soát Route/Sidebar trên UI; READ kiểm soát quyền gọi API lấy dữ liệu.

3. Progressive Disclosure (Ẩn nút)

Ẩn hoàn toàn các nút thao tác mà người dùng không có quyền (không disable mờ gây hiểu lầm cho nhân viên).

4. Realtime Caching Engine (~0.1ms)

Quyền hạn được lưu Cache với Invalidation tức thì khi Admin đổi vai trò/phân quyền, không gây tải N+1 lên PostgreSQL.

5. Tinh gọn theo YAGNI (Tập trung hoàn thiện USERS & SYSTEM)

Chỉ khai báo các quyền thực sự cần thiết cho phân hệ đang xây dựng; dọn dẹp các quyền giả định để hệ thống luôn gọn gàng và dễ bảo trì.

👁️

2. Phân Biệt Quyền `VIEW` (Màn hình) vs `READ` (Dữ liệu)

Tiêu Chí Quyền `USER_VIEW` (Page Access) Quyền `USER_READ` (Data Access)
Mục đích Quyết định xem người dùng có được phép nhìn thấy menu và truy cập URL /users hay không. Quyết định xem người dùng có được phép gọi API đọc dữ liệu tài khoản từ máy chủ hay không.
Lớp bảo vệ (Guard Layer) Frontend Route Guard & Sidebar Menu Filter. Backend DRF ViewSet (Action list, retrieve).
Hành vi khi bị từ chối Ẩn menu trên Sidebar; nếu cố tình nhập URL trực tiếp ➔ Redirect sang trang 403 Access Denied. API trả về mã lỗi 403 Forbidden kèm JSON chi tiết mã lỗi quyền hạn.
📋

3. Danh Mục Quyền Chuẩn Hóa (`USER` & `SYSTEM`)

Mã Quyền (Permission Code) Tên Quyền Hiển Thị Phân Hệ Ánh Xạ Hành Động Backend / Frontend
USER_VIEW Truy cập Màn hình Quản lý Người dùng USER Hiển thị menu /users trên thanh điều hướng Sidebar.
USER_READ Truy vấn & Xem Danh sách Người dùng USER API GET /users/, GET /users/{id}/, GET /users/statistics/.
USER_CREATE Tạo Tài khoản Mới USER Hiển thị nút "Tạo tài khoản", API POST /users/.
USER_UPDATE Chỉnh sửa Thông tin & Trạng thái USER Nút "Sửa", "Khóa/Mở khóa", API PUT /users/{id}/, POST /users/batch-status/.
USER_DELETE Xóa & Chuyển Thùng Rác USER Nút "Xóa", API DELETE /users/{id}/, POST /users/batch-delete/.
USER_EXPORT Xuất Danh sách Ra File USER Nút "Xuất Excel / CSV", API xuất báo cáo.
USER_MANAGE_ROLE Cấu hình Ma trận Phân quyền USER Nút "Ma trận Phân quyền", API POST /roles/{id}/set-permissions/.
SYSTEM_CONFIG Cấu hình Tham số Toàn cục SYSTEM Truy cập các thiết lập tham số hệ thống.

4. Backend Security & Caching Layer (~0.1ms)

Mỗi API call sẽ kiểm tra quyền thông qua Bộ nhớ Cache (Redis / Django Memory Cache) thay vì query SQL lặp đi lặp lại. Khi Admin cập nhật Role hoặc User, Cache sẽ được xóa (Invalidate) ngay lập tức.

# apps/core/permissions.py — Cache-Aware Permission Checker def get_user_permissions(user) -> set: if not user or not user.is_authenticated: return set() cache_key = f"user_perms_{user.id}" perms = cache.get(cache_key) if perms is None: perms = set(RolePermission.objects.filter( role__users=user, role__is_active=True ).values_list('permission__permission_code', flat=True)) cache.set(cache_key, perms, timeout=1800) # Cache 30 phút return perms

Cấu trúc phản hồi chuẩn khi bị từ chối quyền (403 Forbidden JSON):

{ "success": false, "error_code": "PERMISSION_DENIED", "required_permission": "USER_DELETE", "message": "Bạn không có quyền 'Xóa tài khoản' (USER_DELETE) để thực hiện thao tác này." }

5. Frontend Type-Safe Constants & Component ``

// constants/permissions.ts — Bảng mã quyền Type-Safe chuẩn export const PERMISSIONS = { USER: { VIEW: "USER_VIEW", READ: "USER_READ", CREATE: "USER_CREATE", UPDATE: "USER_UPDATE", DELETE: "USER_DELETE", EXPORT: "USER_EXPORT", MANAGE_ROLE: "USER_MANAGE_ROLE", }, SYSTEM: { CONFIG: "SYSTEM_CONFIG", }, } as const; type ValueOf<T> = T[keyof T]; export type PermissionCode = | ValueOf<typeof PERMISSIONS.USER> | ValueOf<typeof PERMISSIONS.SYSTEM>;

Ví dụ sử dụng an toàn trên giao diện React:

// Tự động hoàn thành code (IntelliSense) và báo đỏ nếu gõ sai chính tả <Can permission={PERMISSIONS.USER.CREATE}> <Button type="primary">Tạo tài khoản mới</Button> </Can>
